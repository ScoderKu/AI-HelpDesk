## Python backend runtime

Python is the backend language. FastAPI defines HTTP routes and request handling. Uvicorn is the ASGI server that runs the FastAPI application. They are separate layers: FastAPI is the application framework; Uvicorn is the server process.

The project's backend dependencies include FastAPI, Uvicorn, SQLAlchemy, Alembic, PyMySQL, pydantic-settings and redis.

## FastAPI route model

A route decorator binds an HTTP method and path to a Python function:
```py
@app.get('/api/health')
def health():
    return {'status': 'ok'}
```
FastAPI uses function annotations and Pydantic models to validate request bodies and generate OpenAPI documentation.

HTTP status codes should reflect the result: 200 for successful reads/updates, 201 for creation, 204 for successful operations with no response body, 401 for unauthenticated requests, 403 for authenticated but forbidden operations, 404 for missing/inaccessible resources, 409 for conflicts, 422 for invalid request data, and 503 for temporary dependency failures.

## Pydantic validation

Pydantic models define the accepted shape of request data. Use field constraints for lengths and required fields. Use `extra='forbid'` when unknown fields must be rejected. Use `SecretStr` for password-like input fields to reduce accidental disclosure in representations.

Validation is not authorization. A structurally valid request may still be forbidden because the caller does not own the resource.

## Dependency injection and database sessions

FastAPI dependencies declared with `Depends` provide shared request-level services such as the authenticated user and database session. The project's `get_db` dependency yields a SQLAlchemy Session and closes it in a finally block.

Do not keep a SQLAlchemy Session in a global variable or reuse it across unrelated requests. A session is a unit-of-work object, not a global database connection.

## SQLAlchemy ORM

SQLAlchemy maps Python classes to relational tables. The project uses declarative ORM models and a session factory. Typical operations:
- `db.add(entity)` stages an insert.
- `db.scalar(select(Model).where(...))` fetches one scalar/entity result.
- `db.scalars(select(Model))` returns scalar results.
- `db.commit()` commits the transaction.
- `db.rollback()` undoes the current transaction after an error.
- `db.refresh(entity)` reloads persisted values.

Always handle transaction failures. A failed transaction generally needs rollback before the session can be reused.

## SQLAlchemy URL construction

The project uses `sqlalchemy.URL.create()` to construct the MySQL URL from separate components. This is safer than manually concatenating credentials into a URL string because characters such as `#`, `@` and `/` have special meaning in URLs.

The Compose database host is `mysql` and port is 3306. Hostnames differ between container networks and the developer's Windows host.

## Alembic migrations

Alembic tracks schema versions and applies ordered migration scripts. Use migrations for schema changes rather than editing production tables manually. Review autogenerated migrations: they are candidate code and may miss renames, data transformations or intended constraints.

Before applying a migration to valuable data, back up the database volume and verify the current schema/version.

## Async and blocking operations

FastAPI supports synchronous and asynchronous route functions. An `async def` function should not perform long blocking work directly on the event loop. Use asynchronous libraries or move blocking operations to a worker thread where appropriate. The project uses `asyncio.to_thread` for selected blocking startup/maintenance operations.

## Error handling

Do not expose internal stack traces, SQL, passwords, secret configuration or raw model internals to users. Log enough diagnostic context for maintainers while keeping secrets out of logs. Convert expected dependency failures into controlled HTTP errors.
